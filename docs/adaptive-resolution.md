# 分辨率自适应策略

1280×720 现在是模板与任务坐标的设计基准，不再是设备必须使用的分辨率。不修改模拟器的 wm size、DPI 或用户显示设置。

每张截图独立选择变换，诊断返回 `viewport`：source_size（真实屏幕尺寸）、rotation（顺时针校正角度）、content_rect（校正后画面中的有效区域）、working_size（识别画布）、strategy。模板匹配框 `bounds` 属于识别画布，禁止直接作为 ADB 坐标。

## 候选与选择

1. 比例映射 stretch：将完整画面映射至1280×720，支持同宽高比缩放及界面整体拉伸。
2. 边缘锚定 anchored：按较小缩放系数保留宽高比，扩展识别画布。根据基准ROI中心所在的三分区，分别固定左/中/右、上/中/下位置，适配常见宽屏、平板布局。
3. 黑边裁剪 letterbox：检测连续暗色边缘，使用有效区域归一化。黑边只是候选假设，必须由模板命中验证，不能仅凭暗色背景决定点击区域。
4. 方向：横屏评估0/180°；竖屏评估0/90/180/270°，同时覆盖竖屏窗口内横屏内容与旋转后的游戏画面。

按超过原有0.90阈值的模板数量、分数总和选取一个共同变换，不把不同变换的命中拼到一起。近似同分候选若会给出明显不同的点击位置，清除命中并返回 alignment_confident=false。没有命中时也返回false，不自动点击。

## 坐标与操作

- 匹配中心：识别画布→有效区域偏移/缩放→逆旋转→真实屏幕像素。
- 固定任务点（如结算）：基准坐标先按所选策略处理锚定，再进行同一映射，避免宽屏重复位移。
- 点击/滑动最终按真实截图边界校验，支持1280×720以外的坐标。
- 每次派发输入前重新截图核对尺寸；尺寸改变则取消该输入并报告重新识别。下一次独立诊断/任务循环重新计算变换。
- 手动点击/滑动使用原始设备像素，并要求 expectedSize 与用户看到的截图一致。界面的输入范围随截图尺寸更新。
- 点击后无法定位新画面时，验证结果为 unconfirmed；不能把识别失败报告成“目标已消失”。

## 约束与验证

这项策略解决分辨率、常见宽高比、黑边与方向差异，不保证任意游戏版本、皮肤或完全重排的界面都匹配。低分辨率丢失的图像细节无法恢复；不降低阈值强行点击。保留资源上限：截图输出64MiB，PNG单轴16384、解码分配256MiB，自适应识别8秒预算。

自动测试覆盖960×540、1920×1080、2560×1440、3840×2160、1024×768、2340×1080，另测黑边、宽屏锚定、90/180/270°、坐标边缘、尺寸切换及手动坐标IPC。用真实上游模板构造测试画布并验证识别后回映射的位置，不只测试比例公式。
