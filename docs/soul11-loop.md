# 魂十一（悲鸣）单人循环

2026-10-16 已在实际模拟器完成循环验证。最初 2 轮（69.521 秒）误把开锁图标命名为锁定；收到用户失败截图后已纠正，不能用最初测试证明锁定阵容核验正确。修正后桌面任务 8647651b-725c-4cc5-a473-99248e895cdc 在实际闭锁状态完成 1 轮，耗时 32.277 秒并自动停止。

## 使用入口

任务配置选择「魂十一 · 悲鸣」，设置轮数和时间上限。启动前在游戏中选中悲鸣，配置并锁定阵容，开启自动战斗。需已启用包含 challenge、ready、continue 的按钮模型；本次实测使用 7d2653ba-f0df-4c3f-ad22-84d0309da093。观察功能按照已保存任务层数选择相同的识别流程，不派发点击。

当前支持从已选中悲鸣的挑战页开始循环；有探索和御魂入口的导航分支，但自动滚动查找、点击悲鸣选项尚未实现，其他层数停留时会停止，不猜坐标。实测分辨率为 1920×1080；当前限制为横屏 16:9，其他分辨率仍需独立验证。暂不包含组队邀请、阵容切换和自动购买体力。

## 执行规则

- 场景和按钮保持独立：编排时结合内置 8 类场景模型、启动时固定的已启用按钮模型及层数/阵容模板证据。
- 挑战前：orochi 场景、巫女大蛇标题、锁定阵容、挑战按钮同时成立，且无拾层/神罚/虚无标题冲突；连续画面确认后点击。
- 挑战消耗动作不重试。准备最多重试一次；结算继续最多重试两次，总等待期限不被重试延长。
- 仅本流程发起的挑战，在观察到战斗、结算并稳定返回悲鸣页后才计一轮；从他人已结束的结算页接管不计轮数。
- 识别失败、战败、超时、分辨率变化停止；未知提示不会自动确认。网络/体力弹窗缺少专用分类数据，依靠未知页/动作未确认超时停止，不能声称已能准确区分所有异常弹窗。
- 保留 1500 ms 截图新鲜度检查，开发构建优化图像计算后稳定帧端到端约 1.1 秒。模型冷启动慢帧不用于点击。

## 证据来源

巫女大蛇及其他层数标题模板沿用现有 resources/templates 资源；新增 soul11-lock.png 来源于 training/soul11-review/locked-challenge.png 中经放大并对照上游模板确认的闭锁图标；原 live.png 的开锁图标改存 soul11-unlock.png，明确作为禁止挑战的证据。闭锁模板，按 1280×720 归一化后裁取 [697,653,730,687]，匹配阈值 0.93。模板属于编排状态证据，不加入按钮工作台训练类别。

本次测试日志与逐阶段截图：training/soul11-review/live-two-rounds/。result.json 记录 completed=2、requested=2、success=true；trace.jsonl 记录 43 帧、2 次挑战、2 次准备、4 次继续，最终决策 Complete。结果对应本次模型、设备、阵容与画面，不能替代长时间或跨设备验证。

新增测试覆盖：悲鸣标题与阵容锁缺失、错误层数冲突、两轮计数与停止、未拥有战斗不计数、失败页不点击继续。全量 Rust 56 项通过，2 项硬件测试默认跳过；前端 24 项通过。


## 每帧 DEBUG 耗时

运行日志可筛选 DEBUG，逐帧打印帧号、页面、计算设备、截图、识别合计、按钮预处理/推理/后处理、场景识别、模板匹配、决策、点击、存图及本帧合计，单位 ms。无点击时点击耗时为 0；“未派发”不等于已点击。

识别合计包含子阶段及线程调度开销，不能与子阶段重复相加。本帧合计包含截图到动作处理完成，不含循环休眠、随后日志写入和界面发布。模型初始化发生在循环开始前；单独的「视觉闭环观察」识别合计包含模型加载，并在日志标注。详细数值同时保存在运行目录 trace.jsonl 的 observation.timings。

日志长行支持横向滚动，并可悬停查看完整文本。开锁/闭锁原始截图匹配回归及冲突拒绝测试均通过。

## 2026-10-16 多轮性能优化

用户运行 1ff605a7-c7c4-4f06-adb0-9de116bbacb3：4 轮 115.430 秒，72 帧处理合计约 62.13 秒，额外固定等待约 53 秒。原先战斗一帧约 0.93 秒后再等待 1.5 秒；现改为从截图开始计算目标周期，等待 `max(0,目标周期−已花时间)`，不积压过期帧，不减少挑战前连续画面核验，不放宽 1500 ms 新鲜度限制。

悲鸣循环优先读取 ADB 原始 RGBA8888 帧，验证尺寸、像素格式、12/16 字节头和准确缓冲区长度；不支持时回退 PNG。像素帧供按钮模型与场景模型共享；PNG 仅用于存档。模板只转换/缩放标题和阵容锁所在两个 ROI，保留阈值与开锁冲突保护。其他截图入口仍可用 PNG。

优化后实测 `training/soul11-review/optimized-two-rounds/result.json`：2 轮成功，52.835 秒，最终停止。与用户之前的多轮日志相比，挑战页稳定帧中位数：截图 677.5 → 366.6 ms，识别 345.0 → 164.2 ms，整帧 1078.8 → 539.3 ms；模板约 140 → 5.8 ms。这是不同时间段的现场测量，不是严格固定场景基准；战斗和动画仍占整轮耗时，不能据此声称轮速翻倍。

DEBUG 中增加截图模式 raw / png-fallback，以及解码耗时。raw 路径的截图耗时包含读取、像素转换与存档 PNG 编码，识别阶段不重复解码。新增回归覆盖原始帧头和截断拒绝、像素/PNG往返、ROI开闭锁与悲鸣标题、轮询扣除处理时间。60 项 Rust 测试通过（2 项默认忽略），前端构建及24项测试通过。

Win32 窗口截屏尚未接入。BitBlt/PrintWindow 在模拟器 GPU 渲染、遮挡、最小化时存在黑屏/旧帧风险；未来快路径应验证游戏内容区域、DPI及坐标映射、帧有效性，再配合 ADB 回退。约 10 ms 需要在目标 MuMu 渲染子窗口实测，不能当成端到端保证。

## 2026-10-16 MuMu 原生截图与预处理优化

实现：`src-tauri/src/device/mumu.rs`。魂十一闭环启动时查找运行中的 MuMuNxMain，通过 MuMuManager 的实例列表取得本地 ADB 端口，并比较所选 serial 与实例的 Android boot UUID。仅 UUID 相同且 IPC/ADB 初始画面尺寸、缩略图内容一致时启用原生接口。连接在整个运行期间复用，点击仍通过用户所选 ADB serial。

- MuMu 当前安装版本使用安装根目录连接，加载 `nx_main/sdk/external_renderer_ipc.dll`；不捆绑厂商 DLL。
- display 0 输出为上下倒置的 RGBA；通过 OpenCV RGBA→RGB、垂直翻转恢复 ADB 坐标。保留 1920×1080 原始画面，没有窗口边框或 DPI 坐标换算。
- 不支持的安装布局、未匹配实例、初始画面不一致、连接/截图报错或超时均回退现有 ADB raw/PNG。截图失败后本次运行不再重试 IPC。初始化和后续失败原因记录在 trace.jsonl 的 capture_backend 事件，逐帧 capture_mode 显示实际后端。
- 第三方 DLL 调用放在阻塞工作线程，等待上限 2 秒；超时丢弃结果并关闭本次运行的 IPC 通道。该超时不能强制中止 DLL 内部线程；尚未实现独立进程隔离。没有通过关闭模拟器人为制造 DLL 挂死来验证这一情况。
- 本轮只替换魂十一循环取图，手动单次观察仍走原有路径。已完成一次 8 帧只读观察与两轮闭环；尚未覆盖所有 MuMu 版本、多实例并发、最小化/后台保活等组合。
- 按钮/场景缩放采用 OpenCV INTER_LINEAR，保留 RGB、letterbox padding 和反变换坐标。采样与之前 image Triangle 下采样不完全相同，因此运行了 8 类场景及真实开锁/闭锁截图回归，并完成实际循环；不是全数据集的精度评估，也没有替换模型。
- PNG 采用 Fast + Sub 无损编码；保留每帧 latest.png、关键动作/失败截图，没有以丢弃留档换速度。

实测记录：`training/soul11-review/ipc-performance.json`。对比排除首帧模型冷启动与派发点击的帧，按页面分别取中位数。下表挑战页旧值来自 optimized-two-rounds，新值来自 ipc-two-rounds：

## 点击随机等待与位置偏移（2026-10-16）

闭环实际派发点击前随机等待 120–280 ms；每轴偏移最多为检测框该轴长度的 10%，且不超过 12 个原始截图像素，限定在框中央 50% 区域。窄小框会缩小偏移，非法框拒绝点击。每次真实动作独立采样；只读观察不等待、不派发。

随机等待可被停止操作中断。等待后重新检查任务总时间、截图 1500 ms 有效期，ADB 派发再次检查有效期、坐标范围和取消状态。等待后过期的帧丢弃动作，下一帧重新观察，不把未派发动作计为已点击。原有状态确认、重试上限保持不变。

逐帧 trace 的 click_variation 记录 requested_delay_ms、actual_delay_ms、original_point、point；dispatched 表示是否真的派发。DEBUG 日志展示计划/实际等待以及原始和目标坐标。click_ms 仍只计算 ADB 点击耗时，随机等待计入 total_ms。

随机点击实测：`training/soul11-review/jitter-one-round/result.json` 完成 1 轮并正常停止。挑战计划等待 207 ms、实际 208.8 ms，坐标 (1787,942) → (1797,938)；结算计划等待 252 ms、实际 253.0 ms，坐标 (961,1043) → (967,1045)。偏移可随机取到 0。Rust 全量测试通过后，示例构建遇到增量链接缓存错误，使用进程级 CARGO_INCREMENTAL=0 重建成功，未清理或重置工作区。
