# 独立按钮识别工作台

入口：场景训练 → 按钮识别与坐标。按钮类别不包含场景字段，识别结果不会按场景过滤。场景与按钮的组合规则留给最终编排。

## 素材与标注

- 支持模拟器截图、PNG/JPEG/WebP 图片导入、从已有抽帧素材中选择图片。保存为原分辨率 PNG。
- 同一次截图采集或同段录像使用同一来源批次。导入图片共用工具栏中的批次；另一次独立采集请修改批次。
- 添加按钮名称和唯一标识，例如“挑战 / challenge”。拖拽框选、移动、右下角缩放；右侧可精确编辑原图坐标。
- 点击点是类别级的框内比例，默认 `(0.5, 0.5)`；它随该次模型一起启用，并映射为每次截图的像素坐标。
- 模型预标注只是草稿，需要检查遗漏和错误后保存。现有检测模型可用于首次预标注，包含一些标题等视觉标记；只保留需要训练的按钮。
- 未审核图片不参与训练。没有目标按钮的图片必须明确勾选后保存，才能作为负样本。
- 「数据集与类别」中单行用途只修改该图片，批量操作只修改勾选图片。不会连带更改同批次其他图片。允许同批次图片分别用于训练和验证，不阻止训练；界面提示相似图片可能使验证成绩偏高。训练还会拒绝跨集合的完全相同图片。
- 移出素材只删除清单记录，保留原图。切换标注图片或离开训练页前需要保存或放弃修改。

## 训练与验证

每类至少要有训练和独立验证标注才能启动。这个最低检查不代表样本足够，建议覆盖多次采集、位置、分辨率和动画变化。

训练使用 YOLO11n 目标检测，默认优先 CUDA。任务固定保存标注快照，之后修改标注不会改变正在运行的训练。支持取消，退出应用会终止工作进程。训练后输出每类 mAP@50、整体 mAP@50 和 mAP@50–95，并验证 PyTorch/ONNX 输出一致性。

“启用此按钮模型”仅切换按钮工作台模型，不修改场景分类器或当前御魂控制器。首次未启用自定义模型时使用内置检测模型。

## 坐标测试

截图或导入任意图片，显示按钮名称、置信度、边界框和点击点。坐标原点为原图左上角；缩放和 letterbox 补边会自动还原。支持调整置信度阈值、复制 `{x,y}`，以及把识别结果转成标注草稿。测试不触发游戏点击。

## 本地保存

应用数据目录下 `button-studio/`：

- `annotations.json`：按钮类别、素材清单、标注及审核状态。
- `images/`：按 UUID 保存的原分辨率 PNG。
- `jobs/<UUID>/`：快照、数据集、日志、模型、验证报告。
- `models/<UUID>/`、`active.json`：已启用模型及原子切换指针。

训练脚本为 `training/button_workbench.py`，复用 `training/.venv` GPU 环境。工作进程只训练快照，不自动启用结果。

## 数据集与类别管理

标注页集中显示画布、类别选择和固定保存栏，图片列表可折叠。精确坐标与点击点放在展开项中。采集设置只影响之后导入的素材。

标注大图上方可直接选择本图用途（训练集 / 验证集），选择即保存，只影响本图；无需先完成标注，也不会保存或丢弃正在编辑的框。框选与审核仍需点击「保存标注」。数据集列表提供缩略图，点击「查看大图 / 标注」可打开对应原图。

数据集页支持单图用途、勾选批量划分、编辑真实来源、清理无标注类别、修改类别名称/标识/点击点及删除类别。删除前显示受影响图片和标注数量；删除后保留原图，并将受影响图片设为待审核。类别修改前在 `history/` 保存恢复快照。当前识别模型不会自动替换。

内置类别编码和中文名见 [类别表](button-classes.md)。修改显示名称不改训练编码，也不关联场景。

## 工作台训练与验收流程（2026-10-15）

本轮将脚本中的常用操作接入现有四个页签：

- **标注图片 → 从录像抽帧并挑选素材**：选择本地录像，设置起始时间、间隔和候选帧上限，预览后勾选导入。保留原分辨率；原录像不修改；来源批次记录文件名、文件大小和修改时间，图片名记录秒数。浏览器解码需系统支持对应编码，失败会显示错误。没有自动将相邻帧全选或自动审核。
- **训练模型**：勾选本次参与训练的类别，选择 640 / 960 / 1280 输入尺寸、最大轮数、早停耐心值和计算设备。仅筛选任务快照中的类别及框，不删除工作台原标注。快照仍包含所有已审核图片；仅包含排除类别的图片在本次任务中成为无目标图片。每个所选类别必须有训练和验证框。任务写入 `config.json`，结果记录实际训练轮数。
- **识别测试 → 候选模型与批量验收**：列出历史任务、训练参数、每类训练/验证框数及指标。可选择任意成功导出的任务直接识别，默认仍为当前启用模型。所选模型缺少的数据集类别会明确列出，便于发现 `soulbtn` 未包含在当前模型等问题。历史任务没有记录的参数显示“未记录”，不推测。
- **批量识别验收**：使用全部已审核验证图片，或在数据集页勾选的已审核图片；调用与单图相同的 Rust 推理链路。按置信度从高到低，以同类 IoU ≥ 0.5 一对一匹配，统计命中、漏检、误检、匹配目标的点击落框数。模型不支持的类别单独排除并提示，不能将此分数解释为对全部数据集类别的覆盖率。
- 逐图展示人工框和预测框，可返回该图修正标注。JSON 报告包含模型路径/任务、时间、阈值、标注快照、预测及点击点。报告由“导出验收报告”保存到用户选择的下载位置。改变模型、阈值或数据集后，需要重新验收才能启用候选模型。停止任务后保留已完成部分，不将部分验收作为启用凭据。
- **勾选空白图片预标注**：只处理数据集里明确勾选、未审核且没有框的图片。仅保留现有数据集类别；不新增类别、不覆盖人工框、不自动审核。保存前备份至 `history/prelabels-*.json`；后端再次检查图片状态，冲突时整批拒绝，避免覆盖并发人工修改。
- **启用已验收的候选模型**：由用户检查结果后显式启用。旧 `active.json` 备份至 `history/active-*.json`，新记录包含 `source_job`；可选旧历史任务验收后重新启用。开发本轮功能没有切换实际启用模型。

同批次跨训练/验证仍只提示相似性风险；完全相同图片跨集合仍由训练数据校验拒绝。模型 mAP 高不等于可安全自动点击；模型选择和验收独立于场景编排。

边界：本轮没有把 ONNX 输出通道裁剪做成通用界面功能；已有派生模型可显示来源、测试和启用。录像预览仍需人工挑选，模型预标注仍需逐图视觉复核。自动化流程的层数识别素材缺口不会被这些工具自动消除。
